# 1. 왜 필요한가

지금까지의 결과는 모두 시뮬레이션입니다. 실험 자료가 있으면 다음 세 가지를 실제 값으로 바꿀 수 있습니다.

| 지금의 가정 | 자료로 바꾸는 것 | 영향 |
|---|---|---|
| 실증 기체의 전력 곡선이 제원으로 만든 추정입니다. | 비행 로그의 전압·전류로 전력 곡선을 다시 맞춥니다. | SOC 예상과 최적 속도, 기존 경로 대비 절감 수치 전체 |
| 실제 바람 대신 "나중에 발표된 예보"로 예보 오차를 쟀습니다. | 기체가 잰 바람·지상 풍속계와 예보를 비교합니다. | 출발 판정의 신뢰수준과 필요한 SOC 여유 |
| 계획과 실제 비행이 같다고 가정했습니다. | 계획 SOC·시간과 실제 SOC·시간을 비교합니다. | 계획기의 정확도, 가감속 보정값 |

# 2. 꼭 필요한 것 (1순위)

## 2.1 비행 로그 원본

수정하거나 잘라 내지 않은 원본을 부탁드립니다. 기종에 따라 형식이 다릅니다.

| 기체 | 요청 파일 | 비고 |
|---|---|---|
| ArduPilot 기체 (예: Holybro X650) | 기체에 저장된 DataFlash 로그 (`.bin`), 지상국 텔레메트리 로그 (`.tlog`), 비행 당시의 매개변수 파일 (`.param`) | `.bin`은 기체 SD 카드 또는 Mission Planner의 로그 내려받기로 받습니다. |
| DJI 기체 | 조종기 앱(DJI Pilot 2 등)의 비행 기록 원본 (`.txt`), 가능하면 CSV로 변환한 파일도 함께 | 최근 DJI 비행 기록은 암호화되어 있어, 읽으려면 DJI의 해석 도구와 개발자 앱 키가 필요합니다. 이미 CSV로 변환한 자료가 있으면 그것이 가장 빠릅니다. 원본 저장 위치는 기종·앱 판에 따라 다릅니다 `[확인요망]`. |

로그에 다음 항목이 들어 있어야 합니다. 대부분 기본 설정으로 기록됩니다.

| 항목 | 단위 | 필요한 기록 주기 | 쓰는 곳 |
|---|---|---|---|
| 시각 (시간대 명시, 가능하면 UTC) | – | – | 예보·풍속계와 맞추기 |
| 위치 (위도·경도) | ° | 5 Hz 이상 | 경로와 비교 |
| 고도 (이륙점 기준, 해발 둘 다 있으면 좋음) | m | 5 Hz 이상 | 상승·하강 에너지 |
| 대지속도 (북·동·아래 3축 또는 속력·방향) | m/s | 5 Hz 이상 | 전력 곡선 |
| **배터리 전압·전류** | V, A | 5 Hz 이상 (권장 10 Hz) | **전력 = 전압 × 전류. 가장 중요합니다.** |
| 배터리 잔량 | % | 1 Hz 이상 | 계획 SOC와 비교 |
| 배터리 온도 | °C | 1 Hz | 저온 영향 확인 |
| 기체가 추정한 바람 (DJI 풍속·풍향, ArduPilot `XKF2`의 VWN·VWE) | m/s, ° | 1 Hz 이상 | 예보 오차 측정 |
| 비행 모드·임무 단계 (이륙·경로 비행·호버·착륙·수동 개입) | – | 바뀔 때마다 | 구간 나누기 |

- ArduPilot은 `LOG_BITMASK`에 배터리·GPS·EKF 기록이 켜져 있어야 합니다. 기체 바람 추정은 `EK3_DRAG_BCOEF_X/Y`를 설정해야 기록됩니다. 설정하지 않았다면 그 사실만 알려 주셔도 됩니다.
- DJI 기체의 풍속·풍향 값은 일부 기종·SDK에서만 나옵니다. 없으면 3절의 지상 풍속계 자료로 대신합니다.

## 2.2 비행별 기록표

로그만으로는 알 수 없는 정보입니다. 비행 한 번이 한 줄입니다. 함께 보내는 엑셀 양식(`drone_soc_flight_log_template.xlsx`)에 적어 주시면 됩니다.

| 항목 | 예 |
|---|---|
| 비행 번호, 로그 파일 이름 | F012, `00000012.BIN` |
| 날짜, 이륙 시각·착륙 시각 (시간대) | 2026-11-12, 14:05–14:13 KST |
| 기체 번호, 기종, 펌웨어 판 | X650 #2, ArduCopter 4.5.7 |
| 배터리 번호, 정격 용량(Wh), 충전 사이클, 이륙 전 잔량 | B03, 222 Wh, 41회, 100 % |
| 이륙 중량, 탑재 중량, 탑재물을 내려놓은 지점·시각 | 5.1 kg, 1.0 kg, 배송지 14:09 |
| 이륙점·착륙점 (위도·경도 또는 지명) | 37.40, 127.10 |
| 비행 목적 | 호버 시험 / 정속 왕복 / 배송 임무 / 반복 비행 |
| 계획 속도·고도, 사용한 경로 파일 이름 | 10 m/s, 60 m, `route_A.waypoints` |
| 착륙 후 잔량 | 71 % |
| 특이 사항 | 수동 개입, 중단, 돌풍, 경고 메시지 |

## 2.3 사용한 경로 파일

실험에서 기체에 올린 경로 파일 원본입니다 (ArduPilot `.waypoints`·`.plan`, DJI `.kmz`). 계획한 경로·속도와 실제 비행을 비교하는 데 씁니다.

# 3. 있으면 결과가 크게 좋아지는 것 (2순위)

| 자료 | 내용 | 쓰는 곳 |
|---|---|---|
| 지상 풍속계 기록 | 비행 시간대의 풍속·풍향 (1초 또는 1분 간격), 설치 위치와 높이 | 예보 오차와 기체 바람 추정의 정확도 확인 |
| 정속 왕복 비행 | 같은 직선을 5, 7.5, 10, 12.5, 15 m/s로 왕복 (구간마다 30초 이상 정속) | 전력 곡선과 최대 대기속도. 왕복하면 바람의 영향이 상쇄됩니다. |
| 호버 비행 | 한 자리에서 2분 이상 | 전력 곡선의 기준점 |
| 탑재 중량을 바꾼 비행 | 0, 1, 2 kg 등 같은 경로 | 중량에 따른 전력 증가 |
| 같은 경로 반복 비행 | 같은 경로·속도·중량으로 5회 이상 | 비행마다의 에너지 변동. 기존 경로와 제안 경로를 비교하는 데 필요한 비행 횟수를 정합니다. |
| 상승·하강 구간 | 수직 이동이 있는 비행 | 상승·하강 에너지 |

이미 한 실험 중에 위와 비슷한 비행이 있으면 그 비행만 골라 주셔도 됩니다. 새로 비행을 해야 한다면 1순위 자료를 먼저 검토한 뒤 필요한 비행만 따로 요청드리겠습니다.

# 4. 경로 파일 시험 결과 (해당하는 경우)

DJI 기체가 있다면, 저희가 보낸 DJI 경로 파일(`.kmz`)을 DJI Pilot 2에서 불러온 결과를 부탁드립니다. 비행은 하지 않으셔도 됩니다.

- 불러오기 성공 여부, 실패했다면 오류 문구 그대로
- 성공했다면 경로 화면 캡처, 경로점 2–3개의 고도·속도 표시 값
- 사용한 기종과 DJI Pilot 2 판

# 5. 전달 방법

- **원본 그대로** 보내 주십시오. 변환본만 있다면 어떤 도구로 변환했는지 알려 주십시오.
- 파일 이름에 비행 번호를 넣거나, 2.2의 기록표에 로그 파일 이름을 적어 주십시오.
- 로그에는 비행 위치와 시각이 들어 있습니다. 외부에 내보낼 수 없는 구역이 있으면 그 비행은 빼거나, 이륙점 기준 상대 좌표로 바꿔 주셔도 됩니다 (전력 보정에는 지장이 없습니다).
- 용량이 크면 압축해서 공유 폴더로 보내 주시면 됩니다.

# 6. 최소 요청 (시간이 없을 때)

다음 세 가지만 있어도 전력 모델 보정을 시작할 수 있습니다.

1. 비행 로그 원본 몇 개 (전압·전류·속도·고도가 들어 있는 것)
2. 그 비행들의 이륙 중량과 탑재 중량
3. 비행 날짜·시각과 장소
