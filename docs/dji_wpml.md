# DJI 경로 파일(WPML) 내보내기

계획한 경로를 DJI Pilot 2·FlightHub 2·MSDK V5가 읽는 경로 파일(`.kmz`)로 내보냅니다. v1.2.0에서 더했습니다.

**DJI 기체와 DJI 소프트웨어에서 이 파일을 열어 확인하지 못했습니다.** 확인한 것은 "공식 문서의 구조·요소·값 범위와 일치하는가"와 "다시 읽으면 계획과 같은가"까지입니다. 비행 전에 5절의 점검표를 따라 주십시오.

## 1. 쓰는 법

```bash
dpo-plan --site pangyo --drone m100 --payload 0.5 --dep-hour 15 --wpml m30 --out missions/
```

- `--wpml MODEL`: `m30`, `m30t`, `m300`, `m350`, `m3e`, `m3t`, `m3m`, `m3d`, `m3td` 중 하나. 이륙~착륙 한 번이 파일 하나입니다(왕복은 2개, 순회는 1개).
- `--wpml`을 주면 **계획 단계의 대지속도 상한을 `--wpml-vmax`(기본 15 m/s)로 낮춥니다.** 기종이 낼 수 없는 속도로 계획하지 않기 위해서입니다. 바꾸려면 `--vg-max`를 따로 줍니다.
- `--wpml-finish`: 경로를 마친 뒤의 동작. `autoLand`(기본, 그 자리에 착륙), `goHome`, `noAction`, `gotoFirstWaypoint`
- `--wpml-rc-lost`: 조종기 신호가 끊겼을 때. `goBack`(기본, 이륙점으로 복귀), `goContinue`(경로 계속), `landing`, `hover`

3D 화면(`/3d`)에서는 경로를 만든 뒤 'DJI 경로 파일 (.kmz)'을 누릅니다. 임무 설정의 '대지속도 상한'에 15를 넣고 계획하면 깎이는 구간이 없습니다. API는 `POST /api/wpml {"model": "m30"}`이고 파일은 base64로 옵니다.

```python
from dpo import wpml
out = wpml.from_items(mission_items, model="m30", rth_height=120)   # mission_items: dpo.ardupilot 의 미션 항목
open("route.kmz", "wb").write(out["kmz"])
print(wpml.check(out["kmz"]))                                      # [] 이면 문서의 필수 요소·범위를 지킴
```

## 2. 파일의 구조

```text
route.kmz (ZIP)
 └ wpmz/
    ├ template.kml    편집용. DJI Pilot 2·FlightHub 2 가 읽습니다.
    └ waylines.wpml   실행용. MSDK V5 가 읽습니다.
```

규격은 DJI Cloud API 문서의 DJI WPML 항목(overview, template.kml, waylines.wpml, common element)에서 확인했습니다. 문서 사이트가 이 환경에서 열리지 않아, 같은 문서의 원본인 공개 저장소 `dji-sdk/Cloud-API-Doc`의 2024-11-07 판을 읽었습니다. 폴더 이름 `wpmz`는 문서에 그림으로만 나와 있어 검색 결과로 교차 확인했습니다.

## 3. 계획이 파일에 들어가는 방식

| 계획의 값 | WPML 요소 | 근거와 정한 것 |
|---|---|---|
| 경로점의 경도·위도 | `Point/coordinates` | 경도,위도 순 |
| 경로점의 고도 | `wpml:executeHeight` (+ `wpml:executeHeightMode` = `relativeToStartPoint`), 편집용 파일은 `wpml:height` | **이륙점 기준 상대 고도**로 씁니다. 지도의 고도는 해발이고 WPML의 절대 고도는 타원체고라서, 절대 고도로 쓰면 지오이드고(한국 약 25–30 m)만큼 틀릴 수 있습니다. |
| 구간 대지속도 | `wpml:waypointSpeed` | 문서의 정의가 "그 경로점에서 다음 경로점까지의 속도"입니다. 0.5 m/s 단위로 넣습니다. |
| 구간 안에서 속도가 바뀌는 지점 | 경로점을 하나 더 넣음 | ArduPilot 미션의 '속도 변경점'과 같습니다. |
| 호버 대기 | `wpml:actionGroup` > `hover` (`wpml:hoverTime`), 도착 시 실행 | 그 경로점은 정지 방식으로 지납니다. |
| 꺾이는 경로점 | `wpml:waypointTurnMode` | 멈추지 않고 미리 돕니다. M30·M3E·M3D 계열은 `toPointAndPassWithContinuityCurvature` + `wpml:useStraightLine` 1, M300·M350 RTK는 `coordinateTurn`(이 기종의 지원 목록에 `useStraightLine`이 없습니다). 처음·끝 경로점은 정지 방식입니다. |
| 선회 거리 | `wpml:waypointTurnDampingDist` | 5 m 이하, 이웃 구간 길이의 0.4배 이하. 문서의 "구간 길이 > 양 끝 선회 거리의 합"을 지킵니다. |
| 이륙 | `wpml:flyToWaylineMode` = `safely`, `wpml:takeOffSecurityHeight` | 첫 경로점은 이륙점 바로 위입니다. 안전 이륙 고도는 첫 경로점 높이와 20 m 중 작은 값입니다. |
| 착륙 | `wpml:finishAction` = `autoLand` | 계획이 도착지 착륙까지 SOC를 계산하므로 기본값으로 했습니다. 운용 방식에 맞게 바꾸십시오. |
| 복귀 고도 | `wpml:globalRTHHeight` | 경로를 둘러싼 직사각형(+100 m) 안에서 가장 높은 지형·건물 + 20 m. 경로의 최고 높이보다 낮지 않게 합니다. |
| 기종 | `wpml:droneInfo`, `wpml:payloadInfo` | 문서의 번호표를 그대로 씁니다. 탑재체는 기종의 기본 카메라 번호입니다. |

파일에 넣지 못하는 것은 다음과 같습니다.

- **이륙 전 지상 대기**(이동 장애물을 피하려고 출발을 늦추는 경우). 요약의 경고에 초 단위로 적습니다. 그만큼 기다렸다가 시작해야 합니다.
- **비행 중 속도 갱신.** 파일에는 계획한 구간 속도만 들어 있습니다. DJI 기체에서 비행 중에 속도를 바꾸려면 SDK로 따로 만들어야 합니다 `[확인요망: 사용 기종의 SDK 지원]`.
- **비행 중 남은 구간 미션.** 이륙 항목이 없는 미션은 바꾸지 않습니다.

## 4. 한계

- **전력 모델이 그 기종의 것이 아닙니다.** 프로그램에 있는 DJI 기체 모델은 Matrice 100뿐이고, WPML을 지원하는 기종(M30, M300, M350, Mavic 3E 등)의 전력 곡선은 없습니다. 내보낸 경로와 속도는 계획에 쓴 모델에서 최적인 값이고, SOC 예상은 그 기종에 맞지 않습니다 `[자료필요: 대상 DJI 기종의 정속 비행 전력 기록]`.
- **`wpml:ellipsoidHeight`(편집용 파일의 타원체고)** 에는 상대 고도와 같은 값을 넣었습니다. 타원체고를 계산할 지오이드 자료가 없기 때문입니다. 고도 방식이 상대 고도일 때 DJI Pilot 2가 이 값을 어떻게 쓰는지는 확인하지 못했습니다 `[확인요망]`.
- **기종별 최대 경로 속도**를 문서에서 확인하지 못해 15 m/s로 두었습니다 `[확인요망]`. 넘는 구간은 깎고, 깎은 경우 SOC 예상을 내지 않습니다.
- **경로점 사이 최소 거리와 경로점 개수 한계**를 확인하지 못했습니다. 수평 거리 1 m 미만인 구간(수직 이동)은 경고합니다.
- **이름공간 판**은 문서 예시의 `http://www.dji.com/wpmz/1.0.2`입니다. 최신 DJI Pilot 2가 쓰는 판과 다를 수 있습니다 `[확인요망]`.
- **복귀 경로의 장애물.** 복귀 고도는 경로 주변만 보고 정합니다. 복귀 직선이 비행금지구역을 지나는지는 검사하지 않습니다.

## 5. 비행 전 점검표

1. DJI Pilot 2(또는 FlightHub 2)에서 파일을 불러옵니다. 불러오기가 실패하면 오류 문구를 기록해 주십시오. 규격과 다른 곳을 고치는 데 필요합니다.
2. 지도에서 경로 모양이 3D 화면의 경로와 같은지 봅니다.
3. **경로점마다 고도가 이륙점 기준 상대 고도로 표시되는지** 확인합니다. 내보낸 경로표(.csv)의 `alt_rel_m`과 비교합니다.
4. 구간 속도, 복귀 고도, 신호 두절 동작, 종료 동작을 확인하고 운용 기준에 맞게 고칩니다.
5. **이륙 위치가 계획의 출발지와 같아야 합니다.** 상대 고도의 기준이 실제 이륙점이기 때문입니다. 다른 곳에서 이륙하면 지형·건물과의 이격이 달라집니다.
6. 처음에는 낮은 속도로, 조종사가 언제든 개입할 수 있는 상태에서 시험합니다. 장애물 감지 설정은 기체 기준을 따릅니다.
